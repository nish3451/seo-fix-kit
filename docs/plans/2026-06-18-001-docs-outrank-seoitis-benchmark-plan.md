# docs: Benchmark Proof SEO against Outrank, SEOitis, Okara, and Ahrefs

## Summary

Produce a concise competitive benchmark that compares Proof SEO against Outrank, SEOitis, Okara, and Ahrefs across product promise, workflow, proof quality, pricing, trust posture, agent-assisted execution, data depth, and distribution. The output should turn public competitor research and repo truth into a concrete SEOFixKit self-serve plus agent-assisted product model.

---

## Problem Frame

Outrank, SEOitis, Okara, and Ahrefs all sell autonomous growth or SEO intelligence loops, but from different angles: Outrank emphasizes daily content, free tools, and backlink exchange; SEOitis emphasizes AI-search visibility measurement and gap-to-publishing; Okara emphasizes an AI CMO command center with daily agents, CMS fixes, GitHub PRs, and channel distribution; Ahrefs combines deep SEO/AI data with Site Audit, Patches, MCP, Brand Radar, and Agent A. Proof SEO should not chase generic content volume or try to replace Ahrefs data breadth. The benchmark should clarify where SEOFixKit is already differentiated and how to fold useful competitor patterns into a proof-first self-serve and agent-assisted repair model.

---

## Requirements

- R1. Use current public competitor evidence from official pages first, with recent community or launch signal only as secondary context.
- R2. Ground Proof SEO claims in this repo's current README, prototype context, and competitor benchmark implementation rather than stale memory.
- R3. Compare full SaaS surfaces, not only a Chrome listing, single landing page, or one narrow feature.
- R4. Treat Okara as the execution benchmark for agent feed, CMS fixes, GitHub PRs, Search Console grounding, and self-serve AI CMO packaging.
- R5. Separate confirmed product gaps from positioning gaps so follow-up work is actionable.
- R6. Keep recommendations buyer-facing and truth-safe: no unproven ranking promises, no inflated crawl-scale claims, and no claims beyond current implementation.
- R7. Treat Ahrefs as the data/platform benchmark: SEOFixKit may borrow free-entry, patch-state, AI-agent, and MCP/import ideas, but must not claim parity with Ahrefs keyword, backlink, crawler, rank-tracking, or Brand Radar databases.

---

## Key Decisions

- **Benchmark by buyer job, not feature count:** Feature checklists alone would make Proof SEO look like it should copy content-autopilot tools. The useful question is which buyer job each product owns and where SEOFixKit can win.
- **Treat Proof SEO's wedge as verified repair:** Repo memory and README both anchor the product around rendered proof, false-positive avoidance, and generated fixes. That is the benchmark spine.
- **Use Okara to shape execution, not identity:** Okara's agent suite validates the self-serve plus agent-assisted model, but SEOFixKit should stay narrower and more proof-led than an AI CMO.
- **Use Ahrefs to define data boundaries:** Ahrefs validates that data-backed agents, MCP, patches, AI visibility, and always-on audit matter. SEOFixKit should become an excellent repair agent that can consume external data later, not a smaller Ahrefs clone.
- **Use a docs artifact, not code:** The requested output is strategic knowledge work. No product behavior changes are needed for this pass.
